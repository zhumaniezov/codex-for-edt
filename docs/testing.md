# Проверка версии 0.3

## Автоматические проверки

Команды выполняются из `C:\projects\codex-edt` в PowerShell:

```powershell
.\scripts\build.ps1
.\scripts\start-dev-edt.ps1 -Smoke
# Отдельно, с действующим входом и расходом лимитов Codex:
.\scripts\start-dev-edt.ps1 -Smoke -Live
```

Обычная сборка не вызывает OpenAI. Тестовый Java app-server запускается настоящим дочерним процессом и проверяет отправленные JSONL-запросы. Он находится только в test bundle и не попадает в p2.

Во всех сценариях закрытия проверяется именно принадлежащий сессии Process и известные потомки. Отдельный тест подтверждает, что посторонний дочерний процесс остаётся жив. Они подтверждают публичный document API и end-to-end через View, **не заменяя ручной тест настоящего BSL-редактора конфигурации EDT**. Внешний location берётся через IProject location URI; основной пользовательский проект и информационная база не используются.

## Ручные тесты приёмки

Перед началом закройте предыдущий development EDT и запустите `scripts/start-dev-edt.ps1`. Откройте тестовую конфигурацию, её BSL-модуль и Codex View. Нужен уже действующий вход в Codex. На панели постоянно должен быть индикатор «Только чтение».

| Тест | Действия | Ожидаемый результат |
|---|---|---|
| TC-01 — открыть Codex View | Window → Show View → Other → Codex; перетащить вправо | Видны чаты, короткий статус, composer; интерфейс не блокирует EDT |
| TC-02 — новый чат | После ответа ввести черновик и нажать «Новый чат» | История текущей панели и composer очищены; новый thread создаётся при первом Send; процесс тот же |

| TC-05 — выбрать модель | Выбрать другую запись списка моделей, отправить короткий вопрос | В UI displayName; в диагностике соответствующий model id; ответ получен |

| TC-13 — disk отличается от buffer | Сохранённый файл пустой; в редакторе непустая процедура | Ответ основан на буфере с приоритетом над диском, файл на диске остаётся пустым |

| TC-16 — crash / reconnect | В тестовой среде завершить только дочерний app-server данной View; нажать «Переподключить» | «Отключён»/понятная ошибка, EDT жива; новый процесс и новые запросы работают |
| TC-17 — read-only SHA-256 | Снять хеши файлов тестового проекта до запроса и после, не сохранять dirty editor | Наборы хешей равны; у редактора сохраняется *; автоматических изменений нет |

TC-01, TC-03, TC-06 и TC-14 повторите в **Light** и **Dark**: Window → Preferences → General → Appearance → Theme (при запросе EDT — перезапуск). Проверьте текст, код, ссылки, состояния disabled, ширину правой панели. Полная ручная визуальная приёмка обеих тем остаётся за автором; автоматические тесты проверяют общий renderer без заданных RGB-цветов.

Дополнительно: **⋯ → настройки** — выключить Enter-to-send, убедиться, что Enter добавляет строку и ↑ отправляет; включить обратно. Диагностика по умолчанию скрыта и доступна через tooltip статуса. **Аккаунт** показывает данные сервера. Выход проверяйте только осознанно: он завершает общую авторизацию Codex; в автоматических тестах Logout выполняется исключительно на fake server.

Для TC-16 не завершайте все процессы по имени. Если собственный PID не удаётся надёжно отличить, используйте автоматический тест `errorAndReconnectDoNotLeaveOldProcess`; чужие процессы Codex трогать нельзя.

## Обязательный dirty-editor тест

1. Откройте общий модуль конфигурации в настоящем BSL-редакторе EDT.
2. Сохранённый `Module.bsl` может оставаться пустым. Вставьте в редактор, **не сохраняя**:

```bsl
Процедура Тест()
    Сообщить("Привет");
КонецПроцедуры
```

3. Убедитесь, что на вкладке есть `*`. Снимите выделение, **не нажимайте Ctrl+S**.
4. В Codex спросите: **«Какой код сейчас находится в открытом модуле?»**.
5. В ответе должна быть именно процедура `Тест` с `Сообщить("Привет")`, а не только утверждение, что файл на диске пустой.
6. Выделите `Сообщить("Привет");`.
7. Спросите: **«Что делает выделенный код и в каком контексте он находится?»**.
8. Codex должен объяснить вызов внутри несохранённой процедуры. Звёздочка остаётся, файл не сохраняется.
9. Повторите с большим модулем: окно ограничено 48 000 символами. Codex должен знать, что это фрагмент, и не заявлять, что получил весь несохранённый модуль.

## SHA-256 без изменения проекта

В PowerShell задайте **фактический каталог тестового проекта**, показанный в tooltip диагностики. Перед первым хешированием дождитесь окончания фоновых операций EDT. Не используйте каталог всей workspace с `.metadata`: сама EDT меняет служебные файлы.

```powershell
$testProject = 'C:\путь\к\тестовому-проекту'
$before = @(Get-ChildItem -LiteralPath $testProject -Recurse -File |
    Sort-Object FullName | Get-FileHash -Algorithm SHA256 |
    ForEach-Object { $_.Path + ' ' + $_.Hash })
# Здесь выполнить запрос в Codex. Dirty-документ не сохранять.
$after = @(Get-ChildItem -LiteralPath $testProject -Recurse -File |
    Sort-Object FullName | Get-FileHash -Algorithm SHA256 |
    ForEach-Object { $_.Path + ' ' + $_.Hash })
Compare-Object $before $after
```

Пустой вывод означает равенство. Если EDT параллельно пересобирала проект, разберите отличающиеся пути; не приписывайте их автоматически агенту. Автоматические сценарии используют изолированный файловый проект и сравнивают все его файлы.

## Ограничения и диагностика

Baseline 0.2 вручную принят автором: настоящая конфигурация, BSL-редактор, модель, Skills, streaming, cwd и selection. Это не является автоматической приёмкой нового интерфейса 0.3.

UI установки ZIP в основную EDT, PDE Debug, другие версии Codex/EDT, сетевые и удалённые с диска каталоги, Compare Editor и редакторы без публичного ITextEditor не считаются проверенными этой сборкой. История показывает текст пользователя/ассистента; подробные tool items пока скрыты. Большой dirty-модуль передаётся окном, точный diff не вычисляется. HTTP(S)-ссылки поддерживаются; файловая навигация отложена.

При подготовке UI-тест обнаружил неправильную доставку snapshot и ограничение native placeholder для многострочного Text в Windows; оба исправлены. Live-тест теперь ждёт именно готовую кнопку ↑ и проверяет два серверных ответа, а не промежуточное состояние после Stop.

Известные сообщения хостовой EDT: отсутствие `wmic` в Windows 11, дублирующееся расширение ServersView, working-set filter Resource Navigator. Они не являются ошибками Java-кода плагина. Tycho предупреждает о p2-зависимостях в consumer POM; проверка OSGi/p2 выполняется отдельно.

При ошибке смотрите **Window → Show View → Error Log** и `.runtime/.../edt.log`. Не исправляйте её включением полного доступа. Глобальные Codex config/MCP/Skills не меняются. Следующий этап до отдельного решения автора не начинается.
