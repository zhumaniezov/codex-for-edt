# Настройки Codex for 1C:EDT 0.7

Откройте кнопку **Настройки** (иконка ползунков) в Codex либо **Окно → Настройки → Codex for 1C:EDT**. Основная страница — общие настройки EDT; дочерние: **Codex**, **Серверы MCP**, **Учётная запись**, **Навыки**, **Дополнительно**.

## Два источника настроек

| Слой | Где хранится | Что меняет |
|---|---|---|
| EDT-specific | Eclipse InstanceScope / ScopedPreferenceStore | Язык, Enter, автоматическое открытие, диагностика, передача IDE context |
| Общий Codex | App Server `config/read`, `config/value/write`, `config/batchWrite` | Общие defaults модели/reasoning, конфигурация MCP |

Отдельного `~/.codex-edt` нет. Плагин не открывает и не разбирает пользовательский TOML, auth.json или cookies. Полный ответ config не сохраняется в Eclipse Preferences и не выводится в UI. Файлы конфигурации пишет сам Codex только после явного сохранения в настройках. Перед такой записью показывается подтверждение, поскольку это общая среда других клиентов. `expectedVersion` защищает от перезаписи параллельных изменений; при конфликте обновите данные и повторите выбор.

## Общие и Дополнительно

Язык: **Автоматически / Русский / English**. Автоматический режим использует locale EDT (`Platform.getNL`), неизвестная локаль — английский fallback. После изменения закройте настройки и Codex View, затем откройте заново. Стандартные названия узлов дерева Eclipse Preferences и Show View переводятся по локали самого Eclipse, содержимое страниц и Codex View — по выбранному языку плагина.

**Enter отправляет сообщение** включено по умолчанию; Shift+Enter всегда добавляет строку. При выключенной настройке Enter тоже добавляет строку. Отправка доступна кнопкой со стрелкой, остановка — кнопкой с квадратом.

**Автоматически открывать Codex при запуске** выключено по умолчанию: Eclipse уже умеет восстанавливать оставленную открытой View. Если включить, безопасный отложенный startup открывает панель только при наличии готовых window/page и отсутствии сохранённой View. Ошибка подключения остаётся внутри панели.

**Диагностика** выключена по умолчанию. Версия, raw model id, cwd и thread id доступны в tooltip статуса; подробности процесса/RPC — в Error Log. Переключатель **Передавать контекст редактора и выделение** включён. Если выключить, сохраняется только привязка к физическому каталогу проекта; модуль, selection и dirty buffer не добавляются в prompt. Документ не сохраняется автоматически.

## Codex

Страница читает общую effective configuration без project cwd, показывает sandbox и approval policy для справки. Начальный режим EDT — чтение. Разрешения текущей View выбираются отдельно в composer, проверяются через configRequirements/read и не записываются как глобальный default.

Модель и reasoning выбираются из `model/list`; общие defaults записываются одной атомарной `config/batchWrite`. Они применяются к новым чатам после переподключения. Выбор в composer относится к текущей сессии. Ни список моделей, ни capabilities не дублируются в Preferences. Произвольный редактор всех ключей, permissions и personalization не добавлен.

## Серверы MCP

Источник конфигурации — `config/read`, инвентаризации — `mcpServerStatus/list`, с пагинацией. Показаны имя, enabled, runtime status (если сервер его дал), транспорт из config, auth status и количество tools. Пустое поле runtime означает отсутствие данных, а не успешное подключение. Ошибка RPC отображается отдельно. Обновление может подключать настроенные серверы для получения их каталога; инструменты не вызываются.

Доступны добавить/изменить простой STDIO или HTTP-сервер, включить/выключить, удалить пользовательскую запись, `config/mcpServer/reload`, OAuth через `mcpServer/oauth/login`. Для STDIO аргументы вводятся JSON-массивом строк, например `["--port", "8770"]`; не shell-строкой. Имена нового сервера ограничены латинскими буквами, цифрами, `-` и `_`. Секреты в эту форму не вводятся; env, bearer tokens и headers не редактируются. Неизвестные поля существующей записи сохраняются.

Удаление использует `value:null`, `mergeStrategy:replace`; это подтверждено schema и реализацией config manager Codex 0.153.4. Плагин не пишет свой TOML parser. Профили, project/managed layers и серверы, поставленные plugins, могут запрещать изменение: такое ограничение не обходится. Если запись существует в другом слое, удаление пользовательской записи не удаляет её источник.

**Граница MCP:** внешние инструменты MCP отключаются отдельным session/thread override в диалогах EDT. Иначе они могли бы менять проект вне sandbox. Подключение каталога в Settings не является разрешением агенту выполнять эти tools. В 0.7 добавлено одно исключение: собственный временный MCP `codex_edt_native_<идентификатор>` предоставляет публичные semantic tools текущего проекта EDT. Он проверяет режим, актуальный turn, dirty guard и native approval; в режиме чтения мутации запрещены. Порт и секрет существуют только в текущем экземпляре, запись в общие настройки не создаётся. Подробнее: [семантические инструменты](edt-semantic-tools.md).

## Учётная запись

`account/read` предоставляет тип аккаунта, email и plan при наличии. `account/rateLimits/read` предоставляет окна лимитов: процент использованного лимита, длительность и время сброса. Неизвестные значения не заменяются нулём. Данные backend не выдумываются; display name отсутствует в используемой форме Account schema.

**Войти через ChatGPT** запускает `account/login/start` с `type:chatgpt` и открывает полученный HTTP(S) URL штатным Eclipse browser service. Сервер владеет OAuth, loginId хранится только в памяти. Вход можно отменить. По `account/login/completed` успешный вход переподключает клиента; при необходимости нажмите обновление или повторное подключение. Выход через `account/logout` относится ко всем клиентам общей авторизации, поэтому требует подтверждения и не закрывает EDT.

## Навыки

Read-only список `skills/list`: имя, enabled и описание. Path/scope показываются только при включённой диагностике. Обнаружены stable `skills/config/write`, но toggle сознательно оставлен за рамками этого UX-этапа: текущие Skills используются без изменения. Отдельной базы Skills нет.

## Изоляция настроек и ограничения

Все страницы одного окна Preferences используют отдельный короткоживущий App Server без threads. Закрытие окна завершает его. Основная View сохраняет свой процесс, чат и потоковый ответ. Это исключает применение MCP reload к loaded thread read-only сессии. Один чат по-прежнему обслуживается одним процессом View, каждый Send создаёт только новый turn.

Изменить/удалить можно записи MCP из базового user layer; системные, managed, профильные и проектные записи отображаются, но здесь не редактируются. Add не заменяет существующее имя. Неизвестные поля существующей записи сохраняются без вывода credentials. Конфликт версии требует повторного чтения. Установка самого MCP executable и ввод секретов не реализованы. OAuth работает только для серверов, которые его поддерживают; после завершения обновите список. Поле подробной ошибки отдельного MCP отсутствует в используемой status schema; показывается runtime status и ошибка RPC, если она есть.

Вход/выход в отдельном окне Settings не сбрасывает работающий чат автоматически. После смены аккаунта нажмите «Повторить подключение» в View. Читать общую конфигурацию и список серверов можно без изменения файлов; сохранение настроек выполняет backend после отдельного явного подтверждения.

Файловые ссылки поддерживают существующие пути текущего проекта и `#Lномер`/`:номер`; сложные Markdown URI с URL-encoded локальными путями пока могут потребовать обычный относительный путь. Семантический поиск файла по одному basename не выполняется.

## UI/UX 0.5

Набор страниц и источник настроек сохранены. Header использует компактные icon actions с tooltip, страницы получили более равномерные отступы и интервалы. Настройка Enter/Shift+Enter продолжает действовать для нового composer. Модель и рассуждение берутся из backend; tooltip dropdown показывает полное выбранное имя, если оно не помещается в узкой колонке.

Палитра определяется автоматически по EDT; второй переключатель темы не добавлен. Русские и английские подписи composer, вложений и подтверждений находятся в ResourceBundle. Смена языка по-прежнему требует переоткрыть View/Preferences.

В v0.6 прежний справочный chip заменён selector разрешений. Это состояние текущей View, а не изменение глобального config. Полный доступ требует явного предупреждения; reconnect/resume возвращает режим чтения. Файловые chips живут только в composer, не сохраняются в Eclipse Preferences и не создают собственный attachment storage. MCP, Account и Skills работают прежними сервисами; в этом этапе их функции не расширяются.

## Разрешения 0.6

[Таблица точного отображения режимов](agent-mode.md). Requirements читаются при подключении, выборе режима и перед turn. `permissionProfile/list` проверяет разрешение встроенных профилей; experimental выбор профиля не включён. Модель/рассуждение не меняют режим автоматически. Full access не сохраняется в Preferences.

Windows sandbox используется в существующем режиме Codex. Плагин не запускает elevated setup и не включает full access при ошибке sandbox. Если установка sandbox нужна, выполните её в официальном Codex, подтвердив системный диалог самостоятельно, затем повторите подключение EDT.

## Нативная платформа 0.8

В диагностике доступны версия EDT, готовность native tools и количество объявленных публичных инструментов: 20 в конфигурационном проекте, 16 в расширении. Experimental tools не включены; закрытый formatter service указан среди отключённых. Счётчик инструментов не равен 69 областям исследовательской capability matrix. Эти данные не занимают постоянное место в чате.

В Strict/Ask пользователь может увидеть два подтверждения: штатное разрешение App Server на вызов собственного MCP-инструмента, затем понятный план изменения модели EDT. Плагин не выдаёт постоянных MCP grants и не меняет глобальный config. Дополнительных пользовательских настроек или копии конфигурации Codex для native tools нет.
