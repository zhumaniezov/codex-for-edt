# Codex for 1C:EDT

Личный проект с открытыми исходниками: нативный Java-плагин с боковой панелью Codex для 1C:Enterprise Development Tools. Это сторонний клиент, не официальный продукт OpenAI или фирмы 1С.

## Цель

Создание нативного плагина для 1C:Enterprise Development Tools, который позволит работать с OpenAI Codex непосредственно внутри EDT через отдельную боковую панель агента.

## Текущий статус

**Версия 0.8 — нативная платформа инструментов EDT поверх файлового агента Codex.** Проект выбирается без редактора; модель конфигурации исследуется через native tools. Поддержаны планы создания/изменения метаданных, генерация и дополнение управляемых форм, чтение/редактирование/форматирование BSL через Xtext, Problems и штатная проверка проекта. Начальный режим остаётся «Только чтение»; запись включается явно.

Baseline этапа — **`54d9fca`** (опубликованная 0.7). Рабочие UI, threads, models, approvals и lifecycle сохранены. Возможности API и ограничения отражены в [матрице](docs/edt-capability-matrix.md); публичный контракт не означает автоматическую поддержку всех его операций. Ручная приёмка новой версии проводится по [testing.md](docs/testing.md).

Среда: Windows x86_64, EDT **2026.1.3.25**, JDK **17**, Maven **3.9.16**, Tycho **4.0.5**. На этапе 0.8 повторно проверен Codex **0.154.0-alpha.6.2**; schema сгенерирована заново. Experimental API не включён.

Результаты сборки, native integration, restart и реального Codex фиксируются в [testing.md](docs/testing.md). Тесты записи используют отдельные одноразовые проекты.

## Возможности текущей версии

- Выбор проекта без BSL-редактора, привязка проекта к thread, чтение дерева метаданных через native MCP.
- Реестр 49 корневых типов EDT; базовое создание, изменение свойств и сохранение проверены для 48. Создание Interface отключено. Дочерние реквизиты, табличные части, dimensions/resources, значения перечислений и другие relations определяются descriptors.
- Типы Строка, Число, Булево, Дата, составные и ссылки на справочники, документы, перечисления, планы и другие поддержанные producer types.
- Native формы: генератор EDT, реквизиты, команды/обработчики, группы, поля, таблицы, кнопки; без ручной записи Form.xml.
- BSL: текущий документ, методы/параметры, scope/types, правки по SHA-256, форматирование и native save. Чужой dirty buffer не сохраняется без выбора пользователя.
- Штатный build/Problems, открытие ресурсов и чтение debug state текущего проекта без подключения к базе.
- Единый план метаданных, подтверждение до изменения BM, защита от дубликатов и транзакционный откат при ошибке.
- Dockable-панель **Codex** с оригинальной иконкой и компактным header; история с активной строкой, относительным временем и tooltip полного названия.
- Скруглённый composer с отдельной поверхностью ввода, нижней строкой действий и **круглой кнопкой отправки**, которая меняется на Stop.
- Видимые удаляемые ссылки-вложения: текущий BSL-файл или выбранный файл текущего проекта, максимум пять. Это дополнительный read-only контекст, не загрузка файлов.
- **Новый чат**, список и продолжение серверных threads. Каждый следующий запрос — turn того же чата; при смене проекта нужен явный новый чат.
- Модели с `displayName` и допустимые уровни рассуждения из `model/list`.
- Потоковые ответы, **Отправить / Остановить**, Enter для отправки и Shift+Enter для новой строки.
- Публичный Eclipse-контекст: проект, физический cwd, BSL-модуль, выделение и актуальный dirty buffer без Ctrl+S.
- Native Markdown с подписями ролей, фоном сообщения пользователя и code blocks: абзацы, выделение, списки, inline code; копирование выделения, кода у курсора и последнего ответа через контекстное меню.
- Файловые ссылки внутри текущего проекта открываются в EDT; HTTP(S) — штатным внешним браузером. HTML/JS не выполняются, WebView отсутствует.
- RU/EN, автоматический язык EDT, ресурсы для светлой/тёмной темы и нескольких DPI.
- Страницы настроек: общие, **Codex**, **Серверы MCP**, **Учётная запись**, **Навыки**, **Дополнительно**.
- Чтение Codex config, явное сохранение defaults модели/reasoning, настройка простых MCP STDIO/HTTP-серверов через официальный API.
- Аккаунт и доступные лимиты, браузерный вход ChatGPT, отмена входа и выход; список Skills без изменения.
- Переподключение, отложенный безопасный startup, закрытие собственных процессов и p2-установка.

**Граница инструментов:** в режиме чтения thread/turn получают read-only и запрет повышения разрешений; Внешние MCP и дополнительные средства действий отключены для агентского диалога. Собственный loopback MCP предоставляет чтение модели EDT; запись проверяется отдельно по текущему режиму, проекту, turn и dirty guard. Настройки используют отдельный временный процесс без threads: его MCP reload не обновляет агентский процесс. Общие model/MCP settings изменяются только явным действием с подтверждением; это влияет на общую среду Codex. Плагин не читает credentials и не редактирует TOML вручную. Skills не изменяются. Подробности: [настройки](docs/settings.md).

Dirty buffer до **48 000 символов UTF-16** передаётся целиком; больший модуль — явно обозначенным окном вокруг курсора. Выделение вне окна ограничено 16 000 символами с предупреждением. Сохранённый файл целиком в prompt не добавляется, редактор не сохраняется автоматически.

## Новый интерфейс 0.5

Header, список чатов и диалог отделены от светлеющей/темнеющей поверхности composer. Статус находится в строке «Диалог»; подробности доступны через tooltip/Preferences. Модель и рассуждение выбираются прежним способом. Круглая кнопка поддерживает мышь, Enter/Space и Tab; Enter/Shift+Enter в поле ввода сохраняют настройки.

**Добавление файла:** нажмите **+ → Прикрепить ссылку на текущий файл** или **Выбрать файл проекта…**. До отправки chip можно убрать крестиком. Перед turn пути повторно проверяются в фоне: только существующие файлы внутри физического cwd текущего проекта, включая проверку переходов и ссылок через `toRealPath`. Агент получает относительные пути и может читать сохранённые файлы. Содержимое файлов не копируется в prompt. Актуальный dirty buffer активного BSL-редактора передаётся прежним механизмом и имеет приоритет; другие несохранённые редакторы вложением не передаются. После успешного ответа, нового чата, resume или переподключения вложения очищаются.

**Подтверждения 0.6:** нижний selector меняет разрешения следующих turn. Нативные блоки показывают реальные запросы App Server; ответ отправляется по исходному JSON-RPC id. После разрешения изменения применяет сам Codex. Просмотр diff не является второй стадией Apply. Вложения файлов вне текущего проекта и uploads не поддерживаются. Вложения не разрешают запись.

[Исследование и решение SWT/JFace](docs/ui-ux-research.md). UI v0.5 принят вручную; новые блоки действий и подтверждений требуют проверки в узкой панели и обеих темах.

## Агентный режим 0.6

Нажмите текущий режим внизу composer:

- **Только чтение** — вопросы о коде, включая несохранённый BSL buffer; запись и расширение прав запрещены.
- **Запрашивать разрешение** — изменения файлов и обычные команды внутри физического каталога проекта разрешены. Выход за sandbox требует approval.
- **Строгое подтверждение** — политика Codex `untrusted`: запрос на patch и недоверенные команды. Используйте для первой проверки записи.
- **Подтверждать автоматически** — запросы расширения прав проверяет сам Codex (`auto_review`); возможны ошибочные решения.
- **Полный доступ** — отдельное предупреждение и подтверждение; граница проекта и сетевые ограничения снимаются. Никогда не включается автоматически.

Недоступные политикой Codex варианты выключены. Режим живёт в памяти View; после переподключения, открытия старого чата или перезапуска снова действует чтение. Смена режима сохраняет id текущего чата и переоткрывает серверную сессию перед следующим turn, чтобы прежние grants не переносились неожиданно.

**Перед записью:** выберите нужный EDT-проект в блоке «Проект» или Navigator. Открытый редактор не требуется. Если есть dirty-редакторы, появится список и выбор **Сохранить и продолжить / Отмена**. Во время работы агента редакторы этого проекта защищаются от ввода. Неподдерживаемый редактор нужно закрыть; плагин не продолжает запись при невозможности защитить его. Чистые редакторы обновляются через Eclipse resource refresh, как и Navigator и штатные builders.

В диалоге появляются действия. Двойной щелчок по команде открывает её потоковый вывод и exit code. **Просмотреть изменения** показывает исходный unified diff; **Открыть Eclipse Compare** — штатное сравнение контекста изменённых фрагментов. Создание и удаление имеют отдельные подписи. Выбор файлов и переход в EDT доступны в окне просмотра.

Approval перед действием и review после действия различаются. **Отклонить** относится к ещё ожидающему запросу; уже выполненные изменения не отменяет. Undo, git reset/checkout и собственное применение patch отсутствуют. Обычный workspace-write не обещает approval на каждый файл — именно поэтому есть отдельный строгий режим.

Граница обычного агента — физический `IProject.getLocationURI()`, временные каталоги не добавляются. В approval команда может запрашивать выход за эту границу; проверьте причину и cwd. Network context показывается отдельно. [Протокол и ограничения](docs/agent-mode.md).

## Метаданные EDT без открытого редактора

1. Откройте тестовый проект конфигурации EDT. В Codex нажмите **Выбрать проект**; BSL-редакторы можно закрыть.
2. Выберите **Строгое подтверждение**.
3. Напишите: «Создай справочник Товары с реквизитами Артикул Строка(30), Цена Число(15,2), Активен Булево; табличной частью ДополнительныеКоды с реквизитом Код Строка(50); общий модуль ОбщегоНазначения, серверный».
4. Проверьте native план и нажмите **Разрешить план** либо **Отклонить**.
5. Проверьте объекты в Navigator и сообщения в **Problems**. Повторная команда создания не перезаписывает существующий объект.

Справочники и общие модули создаются публичными фабриками и Big Model EDT. Файловые инструменты Codex продолжают отвечать за BSL и обычные файлы. Семантический инструмент не удаляет метаданные, не обещает Undo и не расширяет текущий проект. Подробнее: [семантические инструменты](docs/edt-semantic-tools.md).

## План развития

После ручной проверки 0.7 можно отдельно согласовать поддержку других объектов метаданных и Undo. Эта версия не добавляет удаление метаданных, формы, регистры или собственный agent loop.

## Сборка

Нужны Full JDK 17 и Maven 3.9.x (от 3.9.4):

```powershell
Set-Location C:\projects\codex-edt
.\scripts\build.ps1
```

Скрипт находит распакованный Maven в проекте или PATH; для своих путей используйте `-JavaHome` и `-MavenHome`. Он запускает `clean verify`, unit/PDE UI tests и p2 verification. Обычные тесты используют тестовый App Server; реальные вход, config и MCP пользователя не меняются. Подробнее: [сборка](docs/build.md).

## Тестирование

Закройте прежний development EDT и выполните:

```powershell
.\scripts\start-dev-edt.ps1
```

1. В отдельной EDT откройте тестовый проект и BSL-модуль.
2. **Окно → Показать панель → Другая… → Codex → Codex** (Window → Show View → Other…). Перетащите панель вправо.
3. Дождитесь подключения; задайте вопрос. Стрелка **Отправить** во время turn сменяется квадратом **Остановить**.
4. Проверьте dirty-модуль со звёздочкой без выделения: «Какой код сейчас находится в открытом модуле?».
5. Откройте настройки кнопкой с ползунками или **Window → Preferences → Codex for 1C:EDT**. Язык меняется после закрытия/открытия View и окна настроек. Названия страниц в дереве Preferences следуют локали Eclipse.
6. Проверьте три запроса в одном чате, Stop, Resume, RU/EN, темы, Markdown и восстановление после перезапуска: [TC-01…TC-50](docs/testing.md).
7. В отдельном тестовом проекте выберите **Строгое подтверждение** и пройдите [TC-51…TC-67](docs/testing.md): edit/create/delete, accept/decline, команды, diff и dirty protection. Завершив проверку, верните **Только чтение**.
8. Для 0.7 закройте редакторы и выполните [TC-68…TC-86](docs/testing.md): native создание справочника/модуля, проверка типов, отказ, дубликат и перезапуск с сохранёнными объектами.

Если executable не найден, передайте `-CodexExecutable 'полный путь к codex.exe'`. Вход доступен на странице **Учётная запись** либо штатной командой `codex login`. После изменения аккаунта в настройках переподключите View. Токены вводить в EDT не требуется.

Автоматические проверки полной EDT:

```powershell
.\scripts\start-dev-edt.ps1 -Smoke
# Настоящие запросы расходуют лимиты Codex пользователя:
.\scripts\start-dev-edt.ps1 -Smoke -Live
# Запись только в создаваемую тестовую фикстуру; тест сам нажимает approval-кнопки:
.\scripts\start-dev-edt.ps1 -Smoke -AgentLive
# Настоящий Codex создаёт метаданные в одноразовом EDT-проекте:
.\scripts\start-dev-edt.ps1 -Smoke -SemanticLive
# Два процесса, одна отдельная workspace для проверки persistence:
.\scripts\start-dev-edt.ps1 -Smoke -SemanticRestart -RestartPhase seed -RestartName semantic-check
.\scripts\start-dev-edt.ps1 -Smoke -SemanticRestart -RestartPhase restore -RestartName semantic-check
```

Тесты используют отдельные workspace и проверяют streaming, контекст, SHA-256 и закрытие процессов. Программная проверка публичного Text Editor API дополняет ручную приёмку настоящего BSL-редактора.

## Нативные инструменты EDT 0.8

Пример задачи: «Через инструменты EDT создай подсистему Продажи, справочник Номенклатура и документ ЗаказКлиента с табличной частью Товары, сгенерируй форму и добавь кнопку Заполнить с обработчиком». Codex сначала запрашивает актуальные descriptors, затем предлагает план. В Strict/Ask подтвердите вызов собственного MCP-инструмента, если App Server запросит его, и проверьте native change plan. Сохраняет модель и выгружает ресурсы сама EDT.

Реестр и точные методы: [EDT Tool Platform](docs/edt-tool-platform.md). В расширении конфигурации доступно чтение; запись не перенаправляется в основную конфигурацию. Удаление root metadata, заимствование расширений, права роли, бинарные макеты, полный Undo и запуск/управление живой базой не объявлены реализованными. Ограниченный removeChild всегда требует отдельного подтверждения. Не пытайтесь обходить неподдержанный native adapter ручным XML.
