# Codex for 1C:EDT

Личный проект: нативный Java-плагин для 1C:Enterprise Development Tools с боковой панелью Codex.

## Цель

Позволить работать с OpenAI Codex непосредственно внутри EDT через отдельную панель агента и официальный локальный `codex app-server`.

## Текущий статус

**Версия 0.2: настоящий Codex через stdio, только чтение.** Плагин запускает дочерний app-server, использует существующий вход пользователя, выбирает модель из каталога и постепенно показывает ответ в Codex View.

Проверенная основа: Windows x86_64, EDT 2026.1.3.25, Full JDK 17, Maven 3.9.16, Tycho 4.0.5. Протокол исследован на **Codex CLI 0.153.4**. Результаты автоматических и реальных проверок — в [docs/testing.md](docs/testing.md).

Первая версия панели уже вручную проверена автором в настоящем BSL-редакторе EDT: открытие, закрепление справа, Send, проект, модуль и выделение работают.

## Возможности текущей версии

- Перемещаемая панель **Codex**, поле сообщения, **Send**, область ответа.
- Подключение к локальному `codex.exe` и кнопка **Переподключить**.
- Проверка входа через `account/read`; токены принадлежат Codex и не читаются плагином.
- Выбор модели через `model/list`: модель по умолчанию, иначе первая видимая.
- Физический каталог текущего проекта EDT как cwd, включая внешнее расположение импортированного проекта.
- Компактный контекст: путь BSL-модуля и непустое выделение, включая несохранённый текст.
- Потоковый текст ответа и состояния подключения/выполнения.
- Один текущий диалог на панель; при смене физического проекта создаётся новый.
- Обработка ошибок и завершение собственных дочерних процессов при закрытии панели.
- Установочный p2-репозиторий и отдельный тестовый экземпляр EDT.

**Изменения файлов не реализованы и не разрешены.** Для thread и turn явно задаётся read-only. Дополнительные инструменты MCP, приложений, плагинов, hooks и субагентов отключены только в дочернем процессе/диалоге. Глобальные настройки, MCP и skills пользователя не меняются.

Выделение ограничено 16000 символами с пометкой сокращения. Весь модуль автоматически не отправляется. Плагин не сохраняет историю диалогов и не содержит собственный OpenAI API-клиент.

## План развития

- Улучшить обработку отмены, повторного соединения и смены версий протокола.
- Добавить выбор модели и управление диалогами.
- Расширить контекст и диагностику через публичные API EDT.
- Отдельным этапом спроектировать diff, **Apply / Reject** и approvals.
- Разрешать запись только после отдельного согласованного этапа разработки.

## Сборка

Нужны Full JDK 17 и Maven 3.9.x от 3.9.4. При первой сборке потребуется интернет для официальных репозиториев зависимостей.

```powershell
Set-Location C:\projects\codex-edt
.\scripts\build.ps1
```

Скрипт находит локальную распаковку Maven в `.tools/apache-maven-*` или `apache-maven-*-bin/apache-maven-*`, затем ищет Maven в PATH. JDK по умолчанию: `C:\Program Files\Axiom\AxiomJDK-Pro-17-Full`. Другие пути задаются через `-MavenHome` и `-JavaHome`.

Команда выполняет `clean verify`, тесты и p2 verification. Обычная сборка использует тестовый дочерний сервер и **не обращается к OpenAI**. Отдельный реальный тест включается явно. Подробности — в [docs/build.md](docs/build.md).

## Тестирование

Закройте прежний тестовый экземпляр EDT, если он использует ту же рабочую область, затем выполните:

```powershell
.\scripts\start-dev-edt.ps1
```

В новой EDT:

1. Откройте тестовый проект и его BSL-модуль.
2. Выберите **Окно → Показать панель → Другая… → Codex → Codex** (**Window → Show View → Other…**).
3. Закрепите панель справа от редактора.
4. Дождитесь состояния «Codex: подключён — только чтение». В диагностике появятся версия и модель.
5. Выделите `Сообщить("Привет");`, перейдите в Codex и отправьте **«Что делает выделенный код?»**.
6. Ответ должен появляться постепенно. В диагностике должен быть физический путь текущего проекта.
7. Убедитесь, что исходные файлы не изменились.

Если Codex не найден, передайте `-CodexExecutable 'полный путь к codex.exe'`. Поиск выполняется в PATH и локальной установке приложения OpenAI Codex. Если требуется вход, выполните штатный `codex login` в PowerShell и нажмите **Переподключить**; вводить ключи или токены в EDT не нужно.

Автоматическая проверка полного EDT с тестовым сервером:

```powershell
.\scripts\start-dev-edt.ps1 -Smoke
```

**Реальный запрос к Codex**, использующий авторизацию и лимиты пользователя:

```powershell
.\scripts\start-dev-edt.ps1 -Smoke -Live
```

Этот сценарий открывает Codex View, создаёт отдельный тестовый проект с BSL-файлом, получает настоящий ответ, проверяет потоковые обновления и SHA-256 файлов, затем закрывает EDT. Основные конфигурации и информационные базы не используются.

## Установка

После успешной сборки установочный ZIP находится здесь:

```text
repositories/io.github.zhumaniezov.codex.edt.repository/target/io.github.zhumaniezov.codex.edt.repository-0.2.0-SNAPSHOT.zip
```

В EDT откройте **Help → Install New Software… → Add… → Archive…**, выберите ZIP и компонент **Codex → Codex for 1C:EDT**. Завершите мастер и перезапустите EDT.

При переходе с 0.1 удалите прежний компонент через **Help → About → Installation Details → Installed Software → Uninstall…**: у личного проекта изменился идентификатор bundle. В рабочей области разработки может остаться вкладка старой View — закройте её и откройте новую через Show View.

p2 собирается и проверяется Tycho. Автоматическая установка в основную пользовательскую EDT не выполняется. ZIP и локальные инструменты не включены в Git; артефакты предварительной версии не подписаны.

## Архитектура

```text
1C:EDT
↓
Codex View (SWT/JFace)
↓
CodexSessionService — контекст, модель, диалог, режим чтения
↓
CodexAppServerClient — JSONL и сопоставление запросов
↓
CodexProcessManager — ProcessBuilder, STDOUT/STDERR, завершение
↓
codex app-server (stdio)
↓
OpenAI Codex
```

Пакеты проекта: `io.github.zhumaniezov.codex.edt`. Чтение контекста использует публичные Eclipse API. Подробности — в [docs/architecture.md](docs/architecture.md).
