# Codex for 1C:EDT

Нативный Java-плагин ADM Global для 1C:Enterprise Development Tools. Добавляет закрепляемую панель **Codex** рядом с редактором. Первая версия работает в локальном тестовом режиме.

## Цель

Создание нативного плагина для 1C:Enterprise Development Tools, который позволит работать с OpenAI Codex непосредственно внутри EDT через отдельную боковую панель агента.

## Текущий статус

Первый этап реализован: панель, локальный тестовый ответ, чтение доступного контекста редактора, Maven/Tycho-сборка и установочный p2-репозиторий.

**Настоящий Codex, OpenAI API и codex app-server пока не подключены.** Плагин не отправляет данные по сети, не изменяет код и не хранит историю чата.

Проверенная среда: **Windows x86_64, EDT 2026.1.3.25, JDK 17 Full, Maven 3.9.16, Tycho 4.0.5**. Получены `BUILD SUCCESS`, успешная проверка p2 и UI-тест в Eclipse и полном продукте EDT. Подробные результаты и границы проверки — в [docs/testing.md](docs/testing.md).

## Возможности текущей версии

- Обычная Eclipse View с названием **Codex**, которую можно открыть, закрыть и закрепить справа от редактора.
- Заголовок, многострочное поле сообщения, кнопка **Send** и область ответа.
- Локальный тестовый ответ на непустое сообщение.
- Снимок доступного контекста при отправке: имя проекта рабочей области, путь открытого `.bsl` и выделенный текст, включая несохранённые изменения.
- Сборка плагина и установочного p2 ZIP; отдельный запуск тестовой EDT без изменения основной установки.

Контекст читается через публичные Eclipse API. Если редактор не предоставляет нужный ресурс или адаптер, контекст может быть неполным. Автотест проверяет `.bsl` в стандартном текстовом редакторе Eclipse внутри EDT. Специфические BSL-редакторы EDT и страницы форм ещё требуют ручной приёмки; семантический API проекта `IV8Project` пока не используется.

## План развития

- Подключить `codex app-server` через отдельную реализацию клиентского слоя.
- Добавить потоковый вывод ответов (streaming), отмену и обработку ошибок соединения.
- Добавить диалоги (threads), историю и восстановление сессий.
- Расширить контекст активного EDT-проекта и BSL-модуля через публичные API EDT.
- Проверить выделенный BSL-код в специализированных редакторах EDT и показывать пользователю передаваемый контекст.
- Добавить просмотр изменений (diff) и действия **Apply / Reject**.
- Добавить запросы разрешений на действия агента (approvals).
- Подключить диагностику EDT и дальнейшую интеграцию с публичным API среды.

Это план следующих этапов, а не возможности текущей поставки.

## Сборка

Нужны Windows x86_64, **Full JDK 17** и **Maven 3.9.x от 3.9.4**. При первой сборке требуется интернет для официальных репозиториев Maven, Eclipse и 1С. Локальная EDT нужна для запуска полного тестового экземпляра, но не для разрешения Maven Target Platform.

Из PowerShell в каталоге проекта:

```powershell
Set-Location C:\projects\codex-edt
.\scripts\build.ps1
```

Скрипт ищет Maven в `.tools/apache-maven-*`, `apache-maven-*-bin/apache-maven-*` и PATH. Значение `-JavaHome` по умолчанию — `C:\Program Files\Axiom\AxiomJDK-Pro-17-Full`; при другой установке передайте путь к своему Full JDK 17. Maven можно указать параметром `-MavenHome`.

Ожидаемый результат — **BUILD SUCCESS**. Скрипт выполняет `clean verify`, UI-тест и проверку p2, хранит зависимости в `.m2`, журнал — в `.runtime/logs`. Дистрибутивы и результаты сборки в Git не включены. Подробные команды и подготовка инструментов — в [docs/build.md](docs/build.md).

## Тестирование

После сборки запустите отдельную тестовую EDT:

```powershell
.\scripts\start-dev-edt.ps1
```

По умолчанию скрипт использует EDT 2026.1 из `%LOCALAPPDATA%\1C\1cedtstart\installations\1C_EDT 2026.1\1cedt`. При других путях передайте `-EdtHome` и `-JavaHome`. Рабочая область тестовой EDT находится в `.runtime/development/workspace`.

В открывшемся окне:

1. Выберите **Окно → Показать панель → Другая…** (в английском интерфейсе — **Window → Show View → Other…**; русский перевод пункта может отличаться).
2. Откройте **ADM Global → Codex**.
3. Перетащите вкладку **Codex** за заголовок к правому краю редактора и отпустите, когда появится контур закрепления.
4. Введите сообщение и нажмите **Send**. Появится «Тестовый ответ Codex».
5. Для проверки контекста откройте BSL-модуль тестового проекта, выделите текст и снова отправьте сообщение.

Автоматическая проверка полного продукта EDT с закрытием тестового окна:

```powershell
.\scripts\start-dev-edt.ps1 -Smoke
```

Для Java-отладки через PDE предусмотрен файл `bundles/com.admglobal.codex.edt/Codex-EDT.launch`. Установка среды «Плагины для 1С:EDT», импорт проектов и запуск **Run / Debug** описаны в [docs/build.md](docs/build.md). Ручные сценарии приёмки — в [docs/testing.md](docs/testing.md).

## Установка

p2-репозиторий **собирается и проходит проверку Tycho**. ZIP после сборки:

```text
repositories/com.admglobal.codex.edt.repository/target/com.admglobal.codex.edt.repository-0.1.0-SNAPSHOT.zip
```

1. В обычной EDT откройте **Справка → Установить новое ПО…** (**Help → Install New Software…**).
2. Нажмите **Add… → Archive…** и выберите этот ZIP. Через **Local…** можно выбрать каталог `target/repository` рядом с ZIP.
3. Выберите **ADM Global → Codex for 1C:EDT**, нажмите **Next**, просмотрите состав и условия предварительной поставки, завершите мастер.
4. Перезапустите EDT и откройте панель через **Show View → Other… → ADM Global → Codex**.

Артефакты предварительной версии не подписаны. GUI-установка в основную пользовательскую EDT ещё не выполнялась: подтверждены сборка p2 и запуск плагина в отдельном экземпляре EDT. ZIP создаётся локально и не входит в исходный Git-репозиторий.

## Архитектура

Планируемая цепочка:

```text
1C:EDT
↓
Codex View
↓
EDT Plugin
↓
Codex Client Layer (подключение транспорта — будущий этап)
↓
codex app-server
↓
OpenAI Codex
```

Сейчас уже есть интерфейс `CodexClient` и локальная реализация `MockCodexClient`. Цепочка заканчивается на ней. Данные редактора передаются клиенту как обычные Java records; UI и чтение контекста отделены от будущего транспорта. Структура Maven/Tycho следует официальному примеру 1С: `bom`, `targets`, `bundles`, `features`, `repositories`, `tests`.

Подробности — в [docs/architecture.md](docs/architecture.md).
